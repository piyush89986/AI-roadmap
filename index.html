  7. 5. EDA, Preprocessing & Statistical Imputation

    Time: 3 se 4 din  |  Depth: practical & critical

    Samjho: Real data mess hota hai. EDA (Exploratory Data Analysis) mein data distributions, skewness, outliers (IQR & Z-score), aur correlation identify kiye jaate hain. Categorical features ke liye One-Hot Encoding aur Label/Ordinal Encoding samjho.

    Visualization: Matplotlib aur Seaborn se correlation heatmaps, box plots, violin plots, aur histograms plot karna seekho.

    Statistical Imputation (Missing Data Handling):

    Missing rows ko delete karna (dropna) valuable data loss karta hai. Statistical imputation mein missing values ko mathematical/statistical properties se fill kiya jata hai:

    Imputation TechniqueStatistical LogicKab Use Karein?Scikit-Learn Implementation
    Mean ImputationColumn ka arithmetic average calculate karke fill karnaSymmetric / Normal distribution data mein (jahan extreme outliers na hon)SimpleImputer(strategy='mean')
    Median ImputationSorted data ka 50th percentile (robust central tendency) lenaSkewed distribution ya jahan extreme outliers hon (e.g. Salary, House Price)SimpleImputer(strategy='median')
    Mode (Most Frequent)Highest frequency / most common value se fill karnaCategorical columns (e.g. City, Gender) ya discrete rating counts meinSimpleImputer(strategy='most_frequent')
    Arbitrary / ConstantKisi fixed constant (e.g. -1, 999 ya 'Missing') se fill karnaJab missingness khud ek signal ho (Missing Not At Random - MNAR)SimpleImputer(strategy='constant', fill_value=...)
    KNN Imputer (Multivariate)Euclidean distance se nearest k-neighbors ka weighted average lenaJab columns aapas mein correlated hon aur patterns preserve karne honKNNImputer(n_neighbors=5)
    Iterative / MICEMultiple Imputation by Chained Equations (har feature ko regression se predict karna)Complex tabular datasets mein jahan statistical precision sabse critical hoIterativeImputer()
    Golden Rule (Prevent Data Leakage): Imputer ko hamesha sirf X_train par .fit() karo aur phir X_train aur X_test dono par .transform() karo. Test data ka mean ya median kabhi train model mein leak nahi hona chahiye!
    Khud check karo:
    • Agar salary column mein extreme outliers hon, to missing salary ke liye mean imputation karoge ya median? Kyun?
    • fit_transform(X_train) aur transform(X_test) ka rule statistical imputation mein kyun zaroori hai?

  8. 6. Scikit-Learn & Core ML Algorithms (Linear, Logistic, Decision Tree, Random Forest)

    Time: 4 se 5 din  |  Depth: implementation, intuition & evaluation

    Samjho: Scikit-Learn (sklearn) Python ki primary machine learning library hai. Industry tabular problems mein in 4 foundational algorithms ka sabse zyada use hota hai:

    AlgorithmTypeCore Math / IntuitionPractical Use CaseScikit-Learn Class
    Linear RegressionRegressionContinuous linear trend line ($y = mx + c$). Residual Sum of Squares (RSS) ko minimize karta hai (OLS).Ghar ki price, salary prediction, sales demand forecastingLinearRegression()
    Logistic RegressionClassificationSigmoid function $\sigma(z) = \frac{1}{1 + e^{-z}}$ se probability ($0$ se $1$) output karta hai. Log-Loss minimize karta hai.Email spam filter (Spam/Not), Loan default approval, Customer churnLogisticRegression()
    Decision TreeClassification & RegressionHierarchical if-else decisions ka tree. Splits Gini Impurity ya Entropy (Information Gain) minimize karke banata hai.Medical diagnosis, credit risk evaluation, customer segmentationDecisionTreeClassifier()
    DecisionTreeRegressor()
    Random ForestEnsemble (Bagging)100+ Decision Trees ka ensemble (Bootstrap Aggregation). Majority voting ya average prediction deta hai. Overfitting drastically kam karta hai.Credit card fraud detection, stock market prediction, high accuracy tabular modelsRandomForestClassifier()
    RandomForestRegressor()

    Core Workflow Pattern:

    train_test_split(X, y) → model = RandomForestClassifier(n_estimators=100) → model.fit(X_train, y_train) → y_pred = model.predict(X_test).

    Model Evaluation Metrics:

    Problem CategoryKey MetricsSamjho
    RegressionMAE, MSE, RMSE, R² ScorePrediction actual numerical value se kitni pass ya door hai.
    ClassificationConfusion Matrix, Accuracy, Precision, Recall, F1-Score, ROC-AUCImbalanced data (jaise 99% non-fraud, 1% fraud) mein sirf accuracy misleading hoti hai; Precision aur Recall se exact quality judge hoti hai.
    Khud check karo:
    • Linear Regression continuous target ke liye aur Logistic Regression probability/classification ke liye kyun use hota hai?
    • Decision Tree overfit jaldi kyun hota hai aur Random Forest use kaise solve karta hai?
    • Ek dataset par LogisticRegression aur RandomForestClassifier dono train karke Classification Report aur Confusion Matrix compare kar sakte ho?

  10. 7. Docker Basic Understanding

    Samjho: Docker tumhare code aur uski dependencies (Python version, libraries, system packages) ko ek lightweight container mein pack kar deta hai. "Mere laptop mein chal raha tha, server par nahi chal raha" wali problem Docker se solve hoti hai.

  11. 8. Cloud Basics & Azure Fundamentals for AI

    Time: 2 se 3 din  |  Depth: core services & cloud mental model

    Samjho: Modern production AI models laptop par nahi balki cloud infrastructure par train aur serve hote hain. AWS aur Azure dono ke foundational services ka mental model samjho:

    CapabilityAWS (Amazon Web Services)Azure (Microsoft)
    Resource GroupingAWS Resource Groups / TagsAzure Resource Groups (saare resources ka logical container)
    Object / File StorageAWS S3 (buckets)Azure Blob Storage (model weights, datasets, logs)
    Compute / Virtual MachinesAWS EC2Azure Virtual Machines (Azure VM) (CPU/GPU instances)
    Container RegistryAWS ECRAzure Container Registry (ACR) (Docker images store karna)
    Serverless ExecutionAWS LambdaAzure Functions (event-driven lightweight scripts)
    Enterprise AI / Foundation ModelsAmazon Bedrock / SageMakerAzure OpenAI Service / Azure ML (GPT-4, LLaMA, embeddings)

    Azure Core Concepts for ML Engineers:

    1. Azure Resource Group: Ek project ke saare components (Storage, Container App, Key Vault, Database) ek hi Resource Group ke andar manage hote hain, jisse billing aur cleanup ek click mein ho jata hai.

    2. Azure Blob Storage: Machine Learning models (model.pkl / onnx) aur raw datasets ko store karne ke liye standard storage hai. Isme Hot, Cool, aur Archive tiers hote hain.

    3. Azure CLI (az): Terminal se Azure login (az login), resource group banana (az group create), aur services deploy karna seekho.

    Khud check karo: Azure Blob storage mein model artifact upload karke access karne ke liye Connection String ya SAS Token kaise use hota hai?

  12. 9. AI to Deploy Architecture & Azure Deployment Flow

    Time: 3 se 4 din  |  Depth: end-to-end production pipeline

    Samjho: Jupyter Notebook ka code production-grade API aur cloud service kaise banta hai? End-to-end model deployment pipeline samjho:

    Step 1: Model Serialization: Trained Scikit-Learn model ko disk par save karo: import joblib; joblib.dump(model, 'model.pkl').

    Step 2: API Wrapper (FastAPI): REST endpoints banao jahan client input JSON bheje aur API prediction return kare:

    @app.post("/predict") → Input Features receive → model.predict([features]) → JSON output return.

    Step 3: Docker Containerization: Code, dependencies (requirements.txt), aur model file ko Docker image mein pack karo:

    docker build -t ai-prediction-api .

    Azure Deployment Options (Real-world):

    Azure Deployment ServiceKab Use Karein?Production Advantage
    Azure Container Apps (ACA)FastAPI Docker container deploy karne ke liye (Recommended)Serverless Kubernetes behind the scenes, automatic HTTPS domain, 0-to-N auto-scaling, low cost.
    Azure App ServiceWeb apps + AI API standard hostingSimple git push ya container deploy, easy custom domain & SSL setup.
    Azure Machine Learning (Azure ML) Managed EndpointsEnterprise-scale ML models & A/B testingBuilt-in model versioning, data drift monitoring, automated health telemetry, Blue/Green rollout.
    Azure FunctionsLightweight inference triggers (event-based)Pay-per-execution, model chhota ho to low cost.

    Azure CLI Deployment Command Flow:

    az login → az acr create --name myacr ... (Container Registry create karo)
    → az acr build --registry myacr --image ai-api:v1 . (Cloud par Docker image build & push)
    → az containerapp create --name ai-service --image myacr.azurecr.io/ai-api:v1 ... (Live public HTTPS API URL mil jati hai!)

    Khud check karo:
    • Trained model ko Pickle/Joblib se save karke FastAPI mein load karke local machine par test kar sakte ho?
    • Azure Container Apps par Docker container deploy karne ka end-to-end flow kya hai?
  13. Phase 4: LLMs, Tokenization & Generative AIModern generative models aur unke core building blocks

  14. 10. LLM (Large Language Model) Fundamentals

    Time: 1 se 2 din  |  Depth: conceptual foundation

    Samjho: LLM (jaise GPT-4, Gemini, Claude, LLaMA) internet-scale text data par trained deep neural networks hain. Inka primary objective agla most probable token predict karna hai. Samjho ki pre-training, instruction fine-tuning, aur in-context learning mein kya farak hota hai.

    Limitations: Hallucination kya hoti hai, context window size ka matlab kya hai, aur knowledge cutoff date kyun hoti hai.

    Khud check karo: Apne dost ko 2 line mein samjha sakte ho ki LLM jawab kaise construct karta hai?

  15. 11. Tokenization & Transformer Architecture

    Time: 2 din  |  Depth: structural overview

    Samjho: AI model text ko direct English ya Hindi mein nahi padhta. Pehle text ko sub-word pieces (Tokens) mein todta hai (BPE algorithm se), phir har token ko ek unique number aur vector diya jata hai.

    Transformer: Aaj ke sabhi LLMs Transformer architecture par chalte hain. Iska core idea “Self-Attention” hai: sentence ka kaun sa word doosre words se kitna deeply connected hai (e.g. "Bank of the river" vs "State Bank").

    Khud check karo: Token kya hota hai? 1 word aur 1 token exact same kyun nahi hote? Token count API pricing ko kaise affect karta hai?

  16. 12. Generative AI Basics & Prompt Engineering

    Time: 1 se 2 din  |  Depth: practical API usage

    Samjho: GenAI text, code, image aur speech generate karta hai. Prompt Engineering ke core patterns seekho: Zero-shot, Few-shot prompting, Chain-of-Thought (step-by-step reasoning), system instructions, aur structured JSON output generation.

    Parameters: Temperature (creativity vs determinism), Top-P, frequency penalty, aur max tokens ka role samjho.

    Khud check karo: Gemini ya OpenAI API use karke Python se structured JSON response return karwa sakte ho?

  17. 13. Embeddings & Vector Databases

    Time: 3 din  |  Depth: achhi tarah samjho

    Samjho: Embedding text ko floating-point numbers ke dense vector (list of floats) mein convert karti hai jo uske semantic meaning ko capture karta hai. Similar meaning wale text ke vectors paas-paas hote hain (Cosine Similarity). Vector DB (ChromaDB, Pinecone, FAISS) in vectors ko fast indexing aur similarity search deta hai.

    Why Vector DB? Traditional SQL database text ka exact keyword match karta hai, jabki Vector DB "meaning" match karta hai (e.g. "fever in kid" matches "pediatric temperature").

    Khud check karo: "car" aur "automobile" ke vectors paas-paas kyun honge? Cosine similarity kaise measure hoti hai?
  18. Phase 5: Advanced AI Systems, RAG & AgentsRetrieval, protocols aur autonomous agentic systems

  19. 14. RAG (Retrieval-Augmented Generation)

    Time: 3 se 4 din  |  Depth: industry essential

    Samjho: LLM ke paas tumhare private data ya custom PDFs ki knowledge nahi hoti. RAG mein pehle documents ko chunks mein split karke embeddings banti hain (Indexing). User query aane par matching context retrieve hota hai (Retriever), aur LLM us context ko padh kar accurate answer generate karta hai (Generator).

    Components: Document Loaders → Text Splitter / Chunking → Embedding Model → Vector Store → Semantic Search → Augmented Prompt → LLM Answer.

    Khud check karo: Agar company ki private policy PDF par chatbot banana ho, to RAG ka kaun sa step kya karega? Hallucinations kaise kam hoti hain?

  20. 15. MCP (Model Context Protocol)

    Time: 1 se 2 din  |  Depth: modern AI standard

    Samjho: MCP (Model Context Protocol) AI models ko external tools, databases, APIs aur file systems se jodne ka universal standard tareeka hai. Jaise USB port kisi bhi device ko laptop se jod deta hai, waise hi MCP AI models ko local/remote tools provide karta hai without writing separate custom integrations.

    Architecture: MCP Host (Chat App / IDE) ↔ MCP Client ↔ MCP Server (Tools, Resources, Prompts).

    Khud check karo: Ek AI agent ko calendar, database ya GitHub repository secure tareeqe se connect karne ke liye MCP kaise kaam karta hai?

  21. 16. LangChain & Agentic AI / Multi-Agent Systems

    Time: 4 se 5 din  |  Depth: autonomous workflows

    Samjho: Chatbot sirf response deta hai, jabki **Agentic AI** autonomous decision making karta hai: wo user goal samajhta hai, plan banata hai, external tools (Calculator, Web Search, SQL DB) use karta hai, aur results evaluate karke self-correct karta hai.

    Frameworks: LangChain aur LangGraph se custom Chains, Memory, Agents aur **Multi-Agent Systems** banaye jaate hain (jahan Coder agent, Researcher agent aur Reviewer agent team ki tarah aapas mein collaborate karte hain).

    Khud check karo: AI Chatbot aur Autonomous AI Agent mein fundamental farak kya hai? ReAct (Reasoning + Acting) loop kaise work karta hai?
  22. Phase 6: Big Data Scale (Optional • End Mein)Agar time mile to cluster distributed computing seekho

  23. 17. PySpark & Distributed Big Data (At the end if had time)

    Time: 3 se 4 din (Optional)  |  Depth: distributed architecture

    Samjho: Jab dataset itna vishal ho jaye (crores of rows / multi-Gigabytes / Terabytes) jo ek single laptop ki RAM mein fit na ho sake, tab Pandas out-of-memory crash ho jata hai. PySpark Apache Spark ka Python API hai jo distributed clusters par parallelly data process karta hai.

    Rule of Thumb:

    Data SizeToolEnvironment
    10-20 lakh rows takPandasSingle laptop / machine
    Crores of rows / TBsPySparkDistributed Cluster / Databricks

    Senior ki advice: Isse bilkul end mein tabhi chhuo jab baki saare stations tick ho chuke hon. PySpark DataFrames, lazy evaluation, aur transformations vs actions ka basic idea kaafi hai.

    Khud check karo: Single-node in-memory processing (Pandas) aur cluster distributed computing (PySpark) mein key architecture difference kya hai?
